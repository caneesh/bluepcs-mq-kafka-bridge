BluePCS MQ–Kafka Bridge

A Spring Boot service that consumes plan notifications from IBM MQ, enriches them via REST, lands the full document in HDFS, and publishes a small claim-check notification to Kafka — acknowledging MQ only when all of that succeeded. This page is deliberately thin: every topic links to the file that is the real documentation.

IBM MQ → parse → enrich (REST+OAuth) → HDFS landing (claim-check) → Kafka notify → ack MQ

Quick start#

Java 11 + Maven. mvn clean package builds and runs the unit tests with no external infrastructure; mvn verify additionally runs the integration tests (embedded Kafka, local-FS HDFS). The local profile runs the whole app with mocks — no MQ, Kafka, HDFS, or credentials needed.

The pipeline, class by class#

One message, one pass. Each stage throws a typed exception the orchestrator maps to an audit event and a redelivery/quarantine decision.

  1. MqMessageListener — JMS listener, CLIENT_ACKNOWLEDGE; poison-message guard; acks only on terminal outcomes.
  2. BridgeOrchestrator — drives the stages, owns error mapping and the quarantine fallback.
  3. JsonMessageParser — validates the planNotification payload; failure ⇒ quarantine, not redelivery.
  4. RestMarketingPlanApiClient — enrichment GET with retry/backoff; bearer token from OAuth2JwtTokenProvider (STS contract: credential headers + JSON body).
  5. EnrichmentWrapperFactory — wraps the raw API response in the output contract the consumer expects.
  6. HdfsSafePayloadWriter — flat landing dir, temp-write → checksum-verify → rename; idempotent by eventId.
  7. KafkaNotificationFactory — builds the claim-check notification (hdfsPath, checksum, eventId, source, schemaVersion).
  8. KafkaEnvelopePublisher — synchronous publish, idempotent producer, acks=all; only then is MQ acked.

Invariants — do not break these#

Ack only after success. The MQ message is acknowledged only on PROCESSING_COMPLETED, MESSAGE_QUARANTINED, or MESSAGE_DISCARDED — anything else redelivers. MqMessageListener
Deterministic eventId. SHA-256 of the JMS message id (payload hash when the id is null) names the HDFS file, keys both Kafka topics, and is the dedup handle everywhere. EventIdGenerator
Checksum-verify BEFORE rename. Corrupt bytes must never reach the landing path — a renamed-then-failed file would satisfy the idempotency check forever. HdfsSafePayloadWriter
Claim-check + schemaVersion. Kafka carries a pointer, HDFS carries the document; schemaVersion presence is how consumers distinguish bridge messages from legacy Talend — bump it on any breaking change. KafkaNotificationFactory
At-least-once, everywhere. Redelivery re-runs the whole pipeline with the same eventId; every downstream must tolerate duplicates.
Quarantine permanent failures. Unparseable payloads are preserved in HDFS errors/ and acked — never looped, never silently dropped. BridgeOrchestrator
Audit never breaks processing. All emit paths are best-effort and swallowed. SafeAuditPublisher
Audit timestamp is an ISO-8601 string — a wire contract pinned by test; the Hive partitioning and gap check depend on it. KafkaAuditPublisherTest
MQ concurrency stays 1. The HDFS exists-check/write/rename sequence is not atomic; concurrent listeners race and duplicate Kafka events. MqConfiguration

Operations · 24×7#

Three self-healing layers: systemd restarts the JVM (with OOM crash-fast flags), a health-driven watchdog timer restarts a wedged-but-alive bridge, and a scheduled Kerberos relogin keeps the HDFS TGT fresh. Dynatrace OneAgent covers JVM/process telemetry; the Control-M monitor adds what it can't see — listener-enabled state and landing-dir backlog. The definitive external signal is MQ-side queue depth (CURDEPTH).

Audit & reconciliation#

Every message leaves an event trail on the audit topic, keyed by eventId — six bridge events plus two consumer events (CLAIM_CHECK_RESOLVED, HIVE_LOAD_COMPLETED, the true terminal state) on the happy path. The audit-hive-consumer Spark job lands them in Hive; audit-gap-check.sh alarms on gaps, stuck messages, and quarantines. Best-effort by design — read the guarantees section before trusting it for anything transactional.

Downstream consumer artifacts#

The DStream job (separate codebase) integrates two drop-ins from this repo: BridgeMessageResolver resolves claim-check notifications back into the legacy inline shape (detection order: schemaVersion present ⇒ bridge; absent ⇒ legacy Talend; missing HDFS file ⇒ already-processed duplicate, skip), and ConsumerAuditEmitter emits the consumer-stage audit events. Consumers must dedupe on eventId.

Testing#

Unit tests run under surefire (mvn test, no infra); *IT classes run under failsafe (mvn verify) with an embedded Kafka broker and local-FS HDFS. Reusable fakes live in test/mock/. When a change touches a cross-system contract, pin the wire format — the timestamp pinning test exists because nothing pinned it and an epoch-vs-ISO mismatch slipped through.
